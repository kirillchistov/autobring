# Курс: «Продвинутый React на практике» — сборка AutoBridge

Формат: каждый модуль = порция теории по сложной React-теме + практический шаг, который
добавляет рабочую часть приложения. К концу курса собран работающий MVP+ (фазы 1–2 из
project-concept.md). Рекомендуемый темп — 1 модуль в неделю, 10–14 модулей.

Стек курса: React 19 + TypeScript, Vite, TanStack Query, Zustand, React Hook Form + Zod,
Tailwind, TanStack Virtual, Vitest/RTL, Playwright. Данные — мок-API (MSW/json-server),
никакого реального парсинга аукционов (см. риски в концепции).

---

## Модуль 0. Фундамент проекта
**Тема:** структура современного React-приложения, TypeScript-конфигурация, архитектура папок (feature-based).
**Практика:** инициализация Vite + TS + Tailwind + ESLint/Prettier; настройка мок-API (MSW)
с фикстурами автомобилей (JP-датасет на 50–100 карточек); базовый роутинг (React Router или
файловый роутинг Next.js — выбрать на курс).
**Результат:** пустой каркас, который открывается и рендерит «Главная / Каталог / Карточка».

## Модуль 1. Компонентная архитектура и композиция
**Тема:** presentational vs container, compound components, render props vs children-as-function,
паттерн «headless UI».
**Практика:** карточка автомобиля (`<CarCard>`) как compound-компонент (`CarCard.Image`,
`CarCard.Price`, `CarCard.Badge`); Layout-компоненты (Header/Footer/Shell).
**Результат:** переиспользуемая карточка авто, используемая и в каталоге, и в «избранном».

## Модуль 2. Сложное состояние на клиенте: useReducer + Context vs Zustand
**Тема:** когда Context начинает «течь» и тормозить; паттерны разделения read/write контекстов;
знакомство с Zustand как современной альтернативой Redux.
**Практика:** глобальное состояние фильтров каталога и корзины «сравнения» на Zustand;
рефакторинг наивного prop-drilling из модуля 1.
**Результат:** фильтры и список сравнения управляются глобальным стором, без prop-drilling.

## Модуль 3. Формы промышленного уровня
**Тема:** React Hook Form (uncontrolled-first подход), схемная валидация через Zod,
динамические поля, кросс-полевая валидация.
**Практика:** форма заявки на подбор (мультиселект способа связи, условные поля «бюджет/сроки»);
многошаговый калькулятор растаможки (объём двигателя → год → тип топлива → итог) как
пошаговая форма с сохранением состояния между шагами.
**Результат:** рабочий калькулятор стоимости «под ключ», валидируемая форма заявки.

## Модуль 4. Данные с сервера: TanStack Query
**Тема:** серверное состояние vs клиентское состояние, кэширование, инвалидция,
optimistic updates, параллельные и зависимые запросы, обработка ошибок/retry.
**Практика:** каталог лотов переезжает на `useQuery` с пагинацией/infinite scroll;
избранное — `useMutation` с optimistic update; синхронизация фильтров каталога с URL
(`useSearchParams` + query-key на основе URL).
**Результат:** каталог с реальной загрузкой, пагинацией и мгновенным откликом на действия.

## Модуль 5. Производительность: список из тысяч лотов
**Тема:** причины лишних ре-рендеров, `memo`/`useMemo`/`useCallback` осознанно (не карго-культ),
виртуализация длинных списков, code-splitting и `React.lazy`/`Suspense`.
**Практика:** подключение TanStack Virtual к каталогу (десятки тысяч мок-лотов);
профилирование через React DevTools Profiler; ленивая загрузка страницы «Компаратор» и «Блог».
**Результат:** плавный скролл каталога независимо от размера датасета, замеренный до/после.

## Модуль 6. Concurrent React и Suspense на практике
**Тема:** `Suspense` для данных (в связке с TanStack Query), `useTransition` для несрочных
обновлений (переключение фильтров без блокировки ввода), skeleton-паттерны, streaming SSR
(если курс на Next.js).
**Практика:** плавное переключение фильтров каталога с `useTransition` без «дёрганого» UI;
skeleton-состояния для карточек и калькулятора.
**Результат:** ощутимо более отзывчивый UI при смене тяжёлых фильтров.

## Модуль 7. Реальное время: живые аукционы
**Тема:** WebSocket/SSE в React, синхронизация серверного стрима с TanStack Query cache,
паттерн «подписка в хуке» (`useAuctionFeed`), борьба с гонками состояний.
**Практика:** мок-сервер WebSocket, транслирующий обновления цены лота; страница
«Аукционы онлайн» с живым тикером цены и таймером до конца торгов.
**Результат:** страница с обновляющимися в реальном времени лотами, как у конкурентов,
но без перезагрузки страницы.

## Модуль 8. Кастомные хуки и переиспользуемая логика
**Тема:** извлечение логики в хуки, границы ответственности хука, тестируемость хуков.
**Практика:** `useCarComparison`, `usePriceCalculator`, `useDealTimeline`, `useDebouncedFilter` —
рефакторинг разросшихся компонентов модулей 2–7 в чистые хуки + тонкие компоненты.
**Результат:** компоненты становятся «глупыми», вся логика — в тестируемых хуках.

## Модуль 9. Личный кабинет, авторизация и защищённые маршруты
**Тема:** паттерны аутентификации в SPA, защищённые роуты, refresh-токены (концептуально),
разделение публичного/приватного состояния.
**Практика:** мок-авторизация (email или «Telegram Login»), личный кабинет с вкладками
«Заявки / Избранное / Алерты», компонент таймлайна сделки (статус-степпер) с анимацией
прогресса (Framer Motion).
**Результат:** рабочий личный кабинет с защищённым доступом и визуальным таймлайном сделки.

## Модуль 10. Компаратор и drag & drop
**Тема:** сложные интерактивные UI: drag & drop (dnd-kit), управляемая сортировка,
доступность (a11y) интерактивных списков.
**Практика:** компаратор из 2–4 авто с возможностью перетаскивания карточек для
изменения порядка сравнения; подсветка отличий характеристик.
**Результат:** полноценный инструмент сравнения — фича, которой нет у конкурентов.

## Модуль 11. Тестирование React-приложения
**Тема:** пирамида тестов для фронтенда, Vitest + RTL для компонентов/хуков,
Playwright для e2e-сценариев, мок сети через MSW в тестах.
**Практика:** unit-тесты калькулятора и хуков; интеграционные тесты формы заявки;
e2e-сценарий «найти авто → добавить в сравнение → отправить заявку».
**Результат:** тестовое покрытие ключевых пользовательских сценариев + CI-прогон.

## Модуль 12. Мультистрана, i18n-каркас и масштабирование архитектуры
**Тема:** feature-sliced/modular архитектура при росте проекта, паттерн «адаптер источника
данных» (JP/KR/CN как взаимозаменяемые провайдеры), основы интернационализации.
**Практика:** обобщение калькулятора и каталога под три страны через единый интерфейс
`CarSource`; переключатель страны ввоза на всех экранах.
**Результат:** те же экраны работают для Японии, Кореи и Китая без дублирования кода.

## Модуль 13. Производительность и метрики продакшена
**Тема:** Core Web Vitals в React-приложениях, бандл-анализ, стратегия code-splitting
на уровне маршрутов, изображения (lazy, responsive, `<picture>`), профилирование в проде.
**Практика:** аудит Lighthouse каталога и карточки авто; оптимизация изображений и
бандла; отчёт «до/после» с цифрами.
**Результат:** измеримо быстрое приложение, готовое к деплою.

## Модуль 14 (опционально). Деплой и админ-панель
**Тема:** деплой SPA/SSR-приложения, окружения (dev/staging/prod), базовые принципы
построения админ-панели поверх тех же React-паттернов.
**Практика:** деплой на Vercel/аналог; мини-админка для управления мок-лотами (CRUD форма
на React Hook Form + таблица с сортировкой/фильтрами — закрепление модулей 3 и 5).
**Результат:** приложение доступно по публичной ссылке, есть базовый инструмент управления контентом.

## Как использовать этот план

- Каждый модуль опирается на предыдущий код — учебный репозиторий растёт линейно, как настоящий продукт.
- Для практики не нужны реальные данные аукционов: используйте мок-датасет (можно синтетически
  сгенерировать 100–300 карточек на основе публичных моделей, упомянутых на сайтах-конкурентах —
  Toyota Sienta, Honda Freed, Nissan Note и т.д. — без копирования текста или фото с этих сайтов).
- Домашние задания естественно формулируются как «доведи фичу модуля N до состояния конкурентов,
  но с преимуществом из project-concept.md» — это держит мотивацию и сразу тренирует продуктовое мышление.
- Модули 0–5 — уверенный middle-уровень React; 6–10 — сложные/продвинутые темы; 11–14 — то, что
  отличает production-ready разработчика от того, кто просто «умеет в JSX».
